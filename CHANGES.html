CHANGES

Unreleased

Changed

  • --debug no longer writes agents/logs/harvey-TIMESTAMP.jsonl. Harvey now records every session as an append-only JSONL log, agents/sessions/NAME.jsonl, beside the Fountain file with the same name (workspace DRs 0036, 0038, 0039 and 0040). It is written whether or not --debug is set; --debug only adds level-debug events, such as the exact messages sent with each request, which rendering and kb ingest skip. Anything that read the old agents/logs file should read the session log instead. The Fountain .spmd files are unchanged.

  • The Fountain .spmd file is rendered from the session log when the session closes. It used to be written live, scene by scene. During a session the file now holds only the title page; the whole screenplay appears at close, or at the next start if the session died (harvey says so). The format is the same, and nothing the live recording wrote is lost: @name routed turns, skill loads, write offers, chunk analysis and /pipeline runs all render from the log. Two differences: tool calls are now shown as [[tool: …]] notes in the turn (the live recorder lost them after tool-result compaction), and a turn that failed is shown with the failure. Anything that reads the current session’s .spmd while it is running will see only the title page; read the session log (agents/sessions/NAME.jsonl) instead.

  • Resume, replay and the session list read the session log. --continue/--resume, /session use, /session show, --replay and /session list rebuild from agents/sessions/NAME.jsonl, not from the Fountain file. A turn that failed or went to a named @route is no longer loaded into a resumed conversation, and a replay skips routed turns. A replay writes a session log of its own (marked replay_of, its inputs origin: replay) and renders its .spmd from it. An older .spmd with no log still loads, through the old reader, for one more release.

  • /rename renames the whole session. The .spmd, the session log and its .blobs directory move together; a name that is already taken is refused (exit 73) and nothing moves.

  • The prompt for a turn is assembled from the session log. When the active model’s prompt limit is known and the conversation is over it, the oldest whole turns are left out as before, but now the choice is made from the log and written to it: the turn’s model_request names the pinned items, the summaries, the recalled knowledge and the tail kept, how many messages were left out and the limit. The prompt is ordered system prompt, pinned context, summaries, recalled knowledge, then the turns, so a context pinned in the middle of a session moves to the front. When the log cannot reproduce the history (a prompt that held a redacted secret) harvey falls back to the old trim. When the model’s prompt limit is not known but its context window is (--context, ollama.context_length, or probed), the prompt is kept to 85% of the window, which leaves room for the reply; before, such a conversation was never trimmed. The model_request records which limit applied.

  • Summaries name what they stand for. The rolling summary is now made by the context assembler: after a reply, when the conversation reaches rolling_summary.warn_at_pct of the prompt limit, every turn but the last keep_turns is summarised by the active model and replaced by one summary, and the session log records the summary with the ids of the events it replaces (a later summary absorbs the earlier one). keep_turns now counts turns, not messages, and warn_at_pct is a share of the prompt limit, not of the window. If the call fails, harvey says so once, leaves the history alone, does not try again for three turns, and the oldest turns are left out as before.

  • Pins: /pin, /unpin, /pins. /pin --text TEXT keeps text in front of the model for the rest of the session; /pin EVENT_ID pins an event of the session log (the line you typed, a reply); /pin kb:record:PROJECT/DR-NNNN and kb:observation:ID pin a knowledge-base row, read with the installed kb. Pins stay ahead of the dialog however long the conversation gets, survive /clear and /summarize, and may take a quarter of the prompt limit together: a pin over that is refused (exit 1) with the existing pins listed by cost. A pin is a pin event in the session log (an unpin event when removed), and each turn’s model_request names the pins. A pinned event is still in the dialog while it is recent, so it is in the prompt twice for a while. /pins lists them with their cost and share of the limit. Pins belong to the session.

  • /context shows what the model sees. It prints the next prompt grouped as system prompt, pins, summaries, recalled knowledge and dialog, with sizes and shares of the prompt limit.

Removed

  • /kb runs the installed kb (workspace DR-0034). /kb ARGS runs kb -db <workspace db> ARGS in the workspace, shows its output, and exits with kb’s status class. Gone from harvey: /kb status, observe, retract, cite, show, check-retractions and the harvey-side search, project list|add, concept and source; use kb’s own (stats, observation add, source retract, source link, observation show, source check-retractions, …). Still harvey’s own: /kb inject, /kb learn ... and /kb project use ID (harvey’s in-session current project). Tab completion reads kb -json verbs once per session. kb must be installed (go install github.com/rsdoiel/knowledge/cmd/kb@latest); without it /kb says so and nothing else is affected. The session log’s kb_result.items is empty for a /kb command now (it named the rows a harvey-side search or show returned); retrieval for the model (kb_call with purpose: retrieval) is unchanged. Not built yet from DR-0034: the write-class gate for model-triggered kb calls (item 5; no model tool runs /kb today), the kb -version minimum (item 3), and kb search for injection (item 2).

  • A native Ollama client replaces any-llm-go (workspace DR-0046). Harvey speaks /api/chat itself, in ollama_chat.go, and the any-llm-go module and the ollama/ollama packages it pulled in are gone from go.mod. Visible changes: harvey sends options.num_ctx set to the window it believes for the model (from ollama.context_length, --context, the model cache or the server), and sends none when the window is unknown; the library always sent 32,000, which cost about 1 GB of memory on a small model. A tool result is sent with role tool and the tool’s name, as Ollama’s API defines, where the library sent it as a user message; llama3.2:3b and qwen2.5:3b answer correctly from it. A tool’s full parameter schema is sent, not only each property’s type and description. Error messages lose the library’s [ollama] provider_error: prefix and read ollama chat: 500 Internal Server Error: ....

  • The cloud route kinds and the S3 reader (workspace DR-0042). Harvey talks only to Ollama-shaped servers on this machine or the local network. Gone: anthropic://, deepseek://, gemini://, mistral:// and openai:// routes, their API-key environment variables, the s3:// document reader and its AWS credentials (/read, /attach, /rag ingest and tab completion), and the anthropic-sdk-go, AWS SDK and other provider modules from go.mod. ollama://, http(s):// and sftp:// stay. A route of a removed kind in agents/routes.json is skipped with a warning at a terminal and stops the run with exit 78 without one; re-add it as an ollama:// route (a skipped route is dropped from the file the next time routes are saved). An s3:// URI is refused with a message that says so. To keep a cloud model, put an Ollama-compatible gateway on your network and point an ollama:// route at it; to keep S3, mount the bucket as a filesystem. The any-llm-go client layer is gone too (next entry).

  • llama.cpp and llamafile support (workspace DR-0033). Harvey supports Ollama and hailo-ollama only. Gone: the two backends and their launch, probe and model-scan code, the --llamafile, --llamafile-url and --llamafile-dir options, HARVEY_LLAMAFILE_DIR, the llamafile:// and llamacpp:// route kinds, assay -llamafile and assay -llamacpp, and the llamafile registry (/model no longer lists, shows or starts them; /model stop and the restart-on-crash prompt for a llamafile are gone). A harvey.yaml with a llamafile: or llamacpp: section is a configuration error (exit 78): delete the section. A persisted route of either kind fails with a message that says it was removed. The last release that carries them is the one before this. assay now talks to Ollama’s native API, not its OpenAI-compatible one.

  • /context add, /context show and /context clear. Pin text with /pin --text TEXT, list with /pins, remove with /unpin N. The single “pinned context” string is now a list of pins. /context with no argument is the new view.

  • /record (start, stop, status) and /help record. Every session is logged from the start, so there is nothing to start or stop, and the log’s file name is chosen with --record-file or /rename NAME. --record and --record-file stay. The harvey-record.7 manual page is gone; harvey-session.7 covers sessions.

Added

  • A complete record of each session. The session log holds every user input, model request and response (with the usage the backend reported), tool call and result, slash command and model switch, so a turn after a model switch is no longer lost. Secret-shaped values (private keys, Authorization and Bearer values, NAME=value for names like password and api_key) are redacted before anything is written; a bare word such as “token” is only flagged.

v0.0.19 (2026-10-10)

Harvey now knows the Raspberry Pi AI HAT+ 2 (hailo-ollama) as a model engine beside Ollama, learns and respects each model’s prompt-size limit, and finds models where each model system keeps them. Several behaviours change for existing setups; they come first.

Added

  • Hailo (AI HAT+ 2) as an engine (harvey DR-0030). hailo-ollama is an engine label over the Ollama client, not a fourth backend, with its own hailo: section in harvey.yaml (hailo.url, default http://localhost:8000) so chat and embeddings can use different servers. The card (/dev/hailo0) and the server (GET /hailo/v1/list) are detected separately; a machine with neither makes no request. A Hailo server found at ollama.url is relabelled hailo at start-up, with one notice and an alias migration. /model list and the pickers show Hailo models beside Ollama’s and the catalog the HAT can run but has not pulled, marked not pulled; /model pull [--yes] NAME pulls from it after a confirmation. Harvey never starts hailo-ollama; it prints the systemctl --user command when the card’s server is stopped. A capability table by engine stops harvey sending tools (HTTP 500) or asking for embeddings, tokenize and ps where Hailo has none, and a failed embedding says that Hailo cannot embed and names Ollama.
  • Per-model prompt limits. hailo-ollama fails with HTTP 500 once a whole prompt passes about 3,000 characters. /model limit sets a model’s limit (seeded at 700 tokens for Hailo’s llama3.2). With a limit known, the system prompt is fitted to 60% of it (skills catalog first, then the tail of HARVEY.md, then a compact preamble), the oldest whole turns are dropped before each send, and a turn over the limit is refused before it is sent. A turn that fails like an oversize prompt is retried on 70%, 45% and 25% of its size and the first success is remembered as the model’s limit. The tool-loop path does not retry yet.
  • harvey completion bash|powershell [-install] writes shell completion for harvey’s verbs, options and help topics, or installs it where the shell loads it. -install never overwrites a file harvey did not write (exit 73). It is separate from the in-session /command completion.
  • make test-models runs live model tests (TestLive_*) against whatever model systems the machine has. A missing system skips its tests with the reason and how to start it.
  • make generate runs cmt over codemeta.json. make build no longer regenerates version.go, CITATION.cff or about.md; make release runs generate first.

Changed

  • The model cache keys capability rows and learned prompt limits by engine and model, so the same name on two engines no longer shares a row. Ollama keeps the bare name; other engines are prefixed. llamafile and llama.cpp rows stored under a bare name are probed once more.
  • /memory mine reads a session too large for the model in parts (sized to the model’s prompt limit when known, halved when a request is cut off), merges and de-duplicates the proposals, and reports a model whose limit is too small to hold the mining instructions as unable to mine. An empty session is recorded as empty and never sent; a truncated or unparseable reply leaves the session unmined and is remembered per session and model so auto-mine does not retry the same model. The review prompt quits at end of input.
  • A RAG retrieval failure (an embedder that is down) is reported once per distinct cause for the life of the session; the prompt still goes on without context. It used to fail silently on every prompt.
  • github.com/rsdoiel/knowledge bumped from v0.0.15 to v0.0.20. Harvey’s own code does not depend on the behaviour changes; the library additions are additive.

Fixed

  • Switching model mid-session no longer drops the --debug log or leaves the transcript naming the previous model. Ollama (/model use, the picker, an alias, or a step dispatched with @name or [model: name]) was fixed first; the llama.cpp path was the last one left.
  • --ollama and -m/--model were overridden by ollama.url and ollama.model in harvey.yaml; see the upgrade notes for the other flags fixed the same way.
  • hailo-ollama models were sent a tools array they cannot take: /api/show returns "model_info": "", which made the capability probe fail to decode, so tool mode stayed auto. The probe now tolerates it and a hef model probes as no tool support.
  • A write offer took the next input line as the file path: piping /exit created an empty file named exit.
  • Test agents no longer scan the machine’s ~/Models, so the suite gives the same result on every machine.

v0.0.17 (2026-09-27)

Breaking (exit codes)

Both harvey and assay now use the workspace exit-code convention (workspace DR-0003; harvey DR-0005) instead of exiting only 0 or 1. A script or an embedding tool that reads either binary’s exit status should check these against the new table (0 ok, 1 negative, 2 usage, 65 data, 66 no_input, 69 unavailable, 70 internal, 73 cant_create, 74 io, 75 temp_fail, 77 no_permission, 78 config — see harvey/CLAUDE.md, “Exit codes”). Five cases that used to exit 0 now fail:

Case Was Now
harvey --continue names a session that does not exist 0 66
harvey --record-file names a path that cannot be created 0 73
harvey.yaml is malformed, in a non-interactive session 0 78
No backend reachable, in a non-interactive session 0 69
assay: every model call fails (the backend is down) 0 69

Every other case that used to exit 1 now exits the more specific code for its cause (2 usage, 65 data, 66 no_input, 69 unavailable, 73 cant_create, 77 no_permission — see exit-codes-survey.md’s baseline table and harvey/decisions/0005-*.md for the full list and the reasoning). harvey --help/-h, --version, -l, help, and assay --help/--version are unchanged, at 0. An error nothing classified is 70, never 1 — a 70 anywhere is a bug, not a documented class. Verified old-versus-new against the v0.0.16 baseline with scripts/compare-exit-codes.py: every changed code above and none unexpected, no exit 70, no hang.

Other

  • An interactive harvey session still warns and continues on a malformed harvey.yaml or an unreachable backend, so nothing changes at a terminal — only non-interactive runs (stdin not a terminal, or --replay without --replay-continue) now fail fast.
  • A surplus positional argument to harvey is now a usage error (2), previously reported as “Unknown flag”.
  • assay finishes its run and writes the report before exiting with the class of the first failure; a prompt’s failing automatic checks are still a result, not a tool failure, and still exit 0.

Added (harvey DR-0006)

  • -json/--json on harvey and assay: a failing startup/flag-parsing error (or, for harvey, a failed non-interactive session — see below) prints as {"error","class","code"} JSON on stderr instead of text, matching kb’s shape. Recognised wherever it sits on the command line, so it still applies when a later flag — or the flag package’s own parse, for assay — is what fails.
  • A non-interactive harvey session (piped stdin, or --replay without --replay-continue) now exits with the class of the first slash command or chat turn that failed, instead of always 0. An interactive session at a terminal is unaffected. /plan’s two previously-unclassified errors (“no backend connected”, “no plan found”) now carry a real class (69, 1); most other command families do not yet and still exit 0 or 70 on a failure — a named follow-up, not done here.
  • /rag setup’s embedding-model auto-pick now confirms its keyword-based guess with one live /api/embed call before committing to it, falling back to another candidate (or warning) when the guess turns out to be wrong. ThoroughProbeModel gets its first caller.
  • github.com/rsdoiel/termlib bumped to the v0.0.9+354195d pseudo-version (no v0.0.10 tag exists yet).

v0.0.15 (2026-06-26)

New features

  • /model mode [MODEL] {structured|prose|inject|none}: set or display the tool-execution strategy for a model. The mode is persisted in the model cache (agents/model_cache.db) and survives sessions and re-probes. Modes: structured (OpenAI tool_calls), prose (JSON-fence fallback), inject (pre-inject file content, no tool calls), none (plain text).
  • File-reference injection (option 1): when a model’s tool mode is inject or when the cache shows it does not reliably call tools, Harvey now automatically scans the user’s prompt for path-like tokens, reads any matching workspace files (≤ 64 KB, text extensions only), and prepends their content as ### File: blocks before sending the prompt. Models that ignore the tools schema can now work with file content without the user manually pasting it.
  • Cannot-read retry (option 2): if a model responds with a phrase indicating it cannot access a file (e.g. “I cannot directly read files on your system”), Harvey retries the turn once with the referenced file content pre-loaded via file-reference injection. The retry uses RunToolLoop when the model is in structured mode so tool calls in the retry response are correctly dispatched.
  • ModelCapability.ToolMode field and ToolMode* constants added to the model cache. The tool_mode column is added to existing databases automatically on first open (idempotent ALTER TABLE).

New features

Remote protocol integration — Harvey can now read files from remote storage over s3://, http://, https://, sftp://, and scp:// URIs anywhere a local path was accepted (/read, /attach, RAG ingest).

  • RemoteReader interface with URI-scheme factory (NewRemoteReader)

  • HTTP/HTTPS backend (stdlib net/http); HTTPS→HTTP downgrade protection

  • Rolling summary: when conversation history exceeds memory.budget_pct (default 25 %) of the model context window, Harvey compresses all but the last six turns into a ~150-token summary with a warning
  • Hybrid retrieval: FTS5 lexical fast-path combined with cosine similarity (when an embedder is active); Recent() fallback replaced by relevance ranking
  • Session stats: memory_stats table in memories.db tracks token budget, injected tokens, compression events, and average tokens/sec per session
